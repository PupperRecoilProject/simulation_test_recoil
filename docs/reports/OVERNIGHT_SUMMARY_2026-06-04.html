你最該知道的發現（依嚴重度）

🔴 高信心 / 嚴重　·　🟡 中等　·　以下每條都已寫進對應的審查報告與 REFACTOR_SCOPE.md。

🔴「久跑超卡、要重開」找到主嫌了 T8 · C5-1

INFINITE 地形的 terrain_cache 是「只增不刪」設計——你每走過一格地形就永久存一塊高度場，從不淘汰。走越久記憶體越大、dict 越查越慢。

這跟你回報的症狀高度吻合。漂亮解：窗口外的地塊直接淘汰（LRU/上限），或改「種子重生」不存整塊。建議實測佐證（印 cache 長度 + 記憶體）。

🔴 sim 其實「不是單一時鐘」 T6 · C3-1

物理走的是「模擬時間」，但 AI 決策節奏綁的是「真實牆鐘」，兩者不同源。筆電負載一高，物理被夾成慢動作、AI 卻照牆鐘跑 → 每模擬步的 AI 次數會漂移，脫離訓練時的固定 dt 假設。

這正是你「印象中時鐘怪怪的」的根。漂亮解：AI 決策也改綁物理步數，整個收斂成單一模擬時鐘。

🔴 後座力倒數計時器疑似「沒接線」 T6 · OPEN_THREADS A8

_update_recoil_warning_timer()（唯一遞減後座力倒數的函式）全 repo 找不到任何呼叫者。若屬實，sim 的隨機後座力事件根本不會觸發——而後座力正是這隻狗的核心賣點。

需要你 / 實測確認。這是典型「設計過但接線斷掉」的功能。

🔴 中央鎖是非重入 Lock + 靠人工紀律的隱性約定 T7 · C4-1

state.lock 是 threading.Lock（非 RLock），而一堆 helper「假定呼叫者已持鎖、自己不鎖」。哪天有人給 helper 加回鎖 → 同執行緒自我死鎖；有人忘了先鎖 → 靜默資料競態。

目前靠紀律維持，很脆弱。建議改 RLock，或拆「公開自鎖 / 私有 _locked」分層。

🔴 雙鍵盤系統重複 T5 · C2-1

同時存在兩套鍵盤處理：GLFW（MuJoCo 視窗）與 GlobalKeyboardDriver（NiceGUI 瀏覽器端），兩邊都綁了重疊的 WASD/QE/IK。行為可能不一致、維護成本翻倍，疑為「視窗→瀏覽器」遷移的中間遺留。

🟡 cp950 啟動編碼 bug T2 · C-S1

滿地 print("✅…") emoji 無編碼保護，非 UTF-8 終端（log 導向檔/CI/自動化）一啟動就 UnicodeEncodeError 直接退出。治本：改用既有 log logger。目前靠 PYTHONUTF8=1 繞過。

🟡 NanoOwl 子程序硬塞主入口 T2 · C-S2

啟動時無條件拉起 tree_demo_server.py（缺 cv2 即崩），且無旗標可關。與機器狗核心無關的功能耦合進主入口，應移出成可選外掛。

🟡 control_mode 是失敗遷移的殘存物 B2

git 考古顯示曾想遷移到乾淨的 OperatingMode/ControlSubMode 列舉，但失敗被整個回退，現在的字串模式是過渡相容用的殘留。重構模式系統時別重蹈覆轍（先測試再動）。

🟡 持鎖跨重活、裝置連接阻塞發布者 T7 · C4-2/3

hard_reset/切模式在鎖內跑重活 → 快速操作時 UI 凍結；裝置掃描在事件回呼裡同步 sleep → 卡住鍵盤/UI 執行緒。應縮小臨界區、耗時連接背景化。

一個重要的「自我糾錯」

原本的報告寫錯，這晚把它修正了。更早一份硬體穩定性報告把「退出硬體卡死」歸因於 _execute_stop 的 self-join。但這晚實際翻現行碼，發現 v4.14.0 早就移除了那段——舊報告過時。

處理方式符合「基於事實的零信任除錯」：沒有去動已經正確的程式碼，改加回歸測試把「不可 self-join」鎖死；同時找出真正的兇手——序列埠交接洩漏（最吻合你「退出後連不上」的症狀），才動手修。
